# HPAL Production Monitor V2.0
## Architecture, Scope, Roadmap, and Implementation Guide

**Repository:** `slimutebal/hpal-production-monitor`  
**Target version:** `V2.0`  
**Status:** Planning / Architecture Baseline  
**Primary deployment:** GitHub Pages PWA  
**Technology direction:** HTML, CSS, Vanilla JavaScript  
**Default route:** `#/monitor`

---

# 1. Purpose

Dokumen ini menjadi arah resmi pengembangan HPAL Production Monitor V2.0.

Tujuan V2.0 adalah mengubah aplikasi dari satu halaman Monitor menjadi aplikasi dengan tiga halaman utama:

1. Monitor
2. Report
3. Settings

Ketiga halaman menggunakan bottom navigation seperti aplikasi mobile.

V2.0 berfokus pada pembentukan struktur aplikasi yang stabil terlebih dahulu. V2.0 bukan refactor penuh dan bukan implementasi seluruh fitur yang direncanakan.

# 2. V2.0 Product Scope

## 2.1 Monitor

Route:

```text
#/monitor
```

Monitor adalah halaman aplikasi yang sudah tersedia saat ini.

Untuk V2.0, Monitor dianggap final dan stabil.

Ketentuan:

- Tidak ada penambahan fitur Monitor.
- Tidak ada perubahan rumus.
- Tidak ada perubahan parser Excel.
- Tidak ada perubahan hasil perhitungan.
- Tidak ada perubahan grafik.

- Tidak ada perubahan format output.
- Tidak ada refactor besar pada logika Monitor.
- Monitor hanya ditempatkan ke dalam app shell dan sistem navigasi baru.

Perubahan yang diperbolehkan:

- Menambahkan page container.
- Menambahkan bottom navigation.
- Menambahkan padding bawah agar konten tidak tertutup navigasi.
- Menambahkan mekanisme route untuk menampilkan dan menyembunyikan halaman.
- Penyesuaian teknis minimal agar Monitor tetap bekerja di struktur V2.0.

Prinsip utama:

```text
Monitor V2.0 output = Monitor versi sebelum V2.0
```

# 5. Application Architecture

V2.0 menggunakan pendekatan Single Page Application sederhana dengan Vanilla JavaScript.

Struktur konseptual:

```text
HPAL Production Monitor
│
├── App Shell
│   ├── Page Container
│   └── Bottom Navigation
│
├── Monitor Page
│
├── Report Page
│   └── HYNC Report Profile
│
└── Settings Page
```

Struktur DOM dasar:

```html
<body>
  <main id="app-pages">
    <section id="page-monitor"></section>
    <section id="page-report"></section>
    <section id="page-settings"></section>
  </main>

  <nav id="bottom-navigation"></nav>

```

Pada V2.0, halaman tidak perlu dihancurkan dan dibuat ulang setiap kali navigasi berubah.

Pendekatan yang direkomendasikan:

```text
Halaman aktif     → ditampilkan
Halaman tidak aktif → disembunyikan
```

Tujuannya:

- Input tidak hilang saat berpindah halaman.
- State Report tetap tersedia.
- Grafik Monitor tidak perlu dibuat ulang tanpa kebutuhan.
- Risiko regresi Monitor lebih rendah.

# 6. Architecture Principles

## 6.1 Monitor Is a Stable Legacy Module

Monitor diperlakukan sebagai modul stabil.

Jangan melakukan refactor besar Monitor bersamaan dengan pembuatan app shell.

Alasan:

- Monitor sudah digunakan.
- Monitor dianggap final untuk V2.0.
- Refactor bersamaan dengan navigasi meningkatkan risiko regresi.
- Sulit membedakan bug arsitektur dan bug refactor jika dilakukan sekaligus.

---

## 6.2 Report Must Be Modular

Kode Report HYNC tidak boleh ditempel langsung sebagai satu script global besar ke dalam `index.html`.

Report HYNC harus ditempatkan dalam module atau namespace terpisah.

Tujuan:

- Menghindari konflik nama variabel dengan Monitor.
- Menghindari konflik `id` HTML.
- Menghindari konflik fungsi seperti `state`, `fileInput`, `goToStep2`, dan `setStep`.
- Memudahkan penambahan ESG dan SLNC.
- Memisahkan parser, template, dan UI.

---

## 6.3 Avoid Global Name Conflicts

Monitor dan generator Report HYNC sama-sama memiliki banyak fungsi dan state.

Kode seperti berikut tidak boleh dibiarkan global:

```javascript
let state = {};
const fileInput = ...;
function goToStep2() {}
function setStep() {}
```

Gunakan ES module atau namespace:

```javascript
const HyncReportPage = (() => {
  const state = {};

  function init() {}
  function show() {}
  function hide() {}
  function reset() {}

  return {
    init,
    show,
    hide,
    reset
  };
})();
```

Pendekatan yang lebih disarankan:

```javascript
export const hyncReportProfile = {
  id: 'hync',
  init,
  parseExcel,
  buildReport,
  reset
};
```

---

## 6.4 Report Must Support Future Profiles

Walaupun V2.0 hanya memiliki HYNC, arsitektur harus mendukung:

```text
V2.0
└── HYNC

V2.1
├── HYNC
├── ESG
└── SLNC
```

Gunakan report profile registry:

```javascript
const reportProfiles = {
  hync: hyncReportProfile
};
```

Pada V2.1:

```javascript
const reportProfiles = {
  hync: hyncReportProfile,
  esg: esgReportProfile,
  slnc: slncReportProfile
};
```

Nama fungsi harus spesifik:

```javascript
parseHyncExcel()
buildHyncReport()
validateHyncInput()
```

Hindari nama yang terlalu generik jika implementasinya masih khusus HYNC:

```javascript
parseExcel()
generateReport()
```

# 8. Bottom Navigation Specification

Bottom navigation harus:

- Berada fixed di bagian bawah layar.
- Selalu terlihat pada ketiga halaman.
- Memiliki icon dan label.
- Menunjukkan halaman aktif dengan jelas.
- Mendukung dark mode dan light mode.
- Tidak menutupi konten.
- Mendukung safe area iPhone.
- Tetap dapat digunakan pada desktop.
- Tidak memicu reload halaman.
- Memiliki area tekan yang cukup besar.

Contoh menu:

```text
Monitor
Report
Settings
```

CSS minimum untuk safe area:

```css
:root {
  --bottom-nav-height: 64px;
}

#bottom-navigation {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  min-height: var(--bottom-nav-height);
  padding-bottom: env(safe-area-inset-bottom);
}

#app-pages {
  padding-bottom:
    calc(
      var(--bottom-nav-height) +
      env(safe-area-inset-bottom)
    );
}
```

Bottom navigation harus memiliki z-index yang cukup, tetapi tidak boleh menutupi dialog atau modal penting.

# 10. Report HYNC Specification

Route:

```text

```

Report HYNC menggunakan alur tiga langkah:

```text
1. Input
2. Area Muat
3. Hasil
```

---

## 10.1 Step 1 — Input

Input yang tersedia:

### Previous Report

- Teks report shift sebelumnya.
- Digunakan untuk mengambil:
  - Date.
  - Daily.
  - WTD.
  - MTD.
  - YTD.

Pada V2.0, previous report mengikuti aturan HYNC dan bersifat wajib seperti generator sumber.

### Weighbridge Excel

- File `.xlsx` atau `.xls`.
- Target sheet: `过磅明细`.
- Parser mencari header yang dibutuhkan.
- File Report terpisah dari file Monitor.
- Pengguna harus upload file secara langsung di halaman Report.

### Man Power and Support

Input:

- Week.
- PIC SCM.
- PIC AWK.
- Manpower AWK.
- Total Manpower.

### Problem and Action

Input:

- Problem.
- Preventive Action.

Problem dan Preventive Action boleh kosong dan menggunakan `-` pada hasil.

---

## 10.2 Step 2 — Area Muat

Aplikasi menampilkan daftar dome dari file timbangan.

Setiap dome harus memilih salah satu area:

```text

DS
```

Setiap dome menampilkan:

- Nama dome.
- Ore class.
- Pilihan area.

Pengguna tidak dapat melanjutkan jika masih ada dome yang belum memiliki area.

## 10.3 Step 3 — Result

Halaman hasil menampilkan:

- Tanggal.
- Shift.
- Tonase On Shift.
- Ritase On Shift.
- Jumlah DT.
- Jumlah ADT.
- Warning jika ada.
- Preview laporan.
- Tombol copy ke clipboard.
- Tombol kembali ke area muat.

Output utama:


Bagian laporan:

```text

```

Nilai produksi:

```text

```

# 11. Report HYNC Calculation Rules

## 11.1 On Shift

```text
On Shift tonnage = jumlah seluruh net weight / 1000
On Shift ritase  = jumlah record valid
```

## 11.2 Daily

Day Shift:

```text
Daily = On Shift
```

Night Shift pada tanggal yang sama dengan report sebelumnya:

```text
Daily = Previous Daily + On Shift
```

Night Shift dengan previous report yang berbeda tanggal:

```text
Daily = On Shift
```

## 11.3 WTD, MTD, and YTD

```text
WTD = Previous WTD + On Shift
MTD = Previous MTD + On Shift
YTD = Previous YTD + On Shift
```

Aturan ini harus tetap sama dengan generator HYNC sumber, kecuali ada perubahan requirement yang disetujui terpisah.

# 12. Report State Behavior

State Report harus tetap tersedia saat pengguna berpindah halaman:

```text
Report → Monitor → Report
```

Data yang sebaiknya tetap tersimpan selama aplikasi masih terbuka:

- Previous report text.
- File yang telah diproses.
- Input manpower.
- Problem.
- Preventive action.
- Dome assignment.
- Generated report.
- Step aktif.

Untuk V2.0, state cukup disimpan di memory.

Tidak perlu disimpan permanen ke database atau IndexedDB.

State boleh hilang ketika:

- Browser ditutup.
- Tab ditutup.
- Aplikasi di-refresh.
- Pengguna menekan reset.
- Service worker melakukan update yang membutuhkan reload.

# 13. Report and Monitor Data Separation

Pada V2.0:

```text
Monitor upload ≠ Report upload
```

Ketentuan:

- Monitor membaca file sendiri.
- Report membaca file sendiri.
- Report tidak mengambil hasil dari Monitor.
- Monitor tidak mengambil hasil dari Report.
- Pergantian halaman tidak melakukan transfer otomatis.
- Integrasi satu kali upload untuk beberapa halaman bukan scope V2.0.

Alasan:

- Mengurangi risiko terhadap Monitor.
- Format parser dapat berbeda.
- Mempermudah pengujian.
- Menjaga scope V2.0 tetap terkendali.

# 14. Contractor Data Direction

V2.0 tidak mengimplementasikan Settings kontraktor.

Namun, arah arsitektur adalah satu sumber data kontraktor:

```text
Contractor Directory
        │
        ├── Monitor
        ├── Report HYNC
        ├── Report ESG
        ├── Report SLNC
        └── Settings
```

Report HYNC tidak seharusnya memiliki daftar DT-kontraktor besar yang berdiri sendiri jika data yang sama sudah tersedia di aplikasi.

Target:

- Gunakan `contractor-assignment.js` atau service bersama.
- Report HYNC membaca mapping kontraktor melalui adapter.
- Monitor tidak boleh berubah perilakunya.
- Settings di versi berikutnya akan menjadi UI untuk mengelola sumber data tersebut.

Jika penggunaan sumber bersama menimbulkan risiko terhadap Monitor pada V2.0:

- Buat adapter read-only.
- Jangan mengubah mekanisme Monitor.
- Dokumentasikan duplikasi sementara.
- Hapus duplikasi pada fase khusus setelah V2.0 stabil.

# 16. Service Worker and PWA Requirements

V2.0 tetap harus berfungsi sebagai PWA.

Service worker harus diperbarui agar mencache:

- `index.html`.
- `manifest.webmanifest`.
- `contractor-assignment.js`.
- CSS app shell.
- CSS bottom navigation.
- CSS Report HYNC.
- JavaScript app.
- JavaScript router.
- JavaScript bottom navigation.
- JavaScript Report page.
- JavaScript HYNC profile.
- JavaScript Settings placeholder.
- Icon PWA.

Contoh arah app shell cache:

```javascript
const APP_SHELL = [
  './',
  './index.html',
  './manifest.webmanifest',
  './contractor-assignment.js',
  './assets/css/app-shell.css',
  './assets/css/bottom-navigation.css',
  './assets/css/report-hync.css',
  './assets/css/settings.css',
  './js/app.js',
  './js/router.js',
  './js/components/bottom-navigation.js',
  './js/pages/report/report-page.js',
  './js/pages/report/profiles/hync-profile.js',
  './js/pages/settings/settings-page.js'
];
```

Ketentuan:

- Cache name harus dinaikkan saat V2.0 dirilis.
- Cache lama harus dibersihkan saat activate.
- Cross-origin request tetap tidak boleh dicache.
- Google Apps Script contractor sync tetap melalui network.
- Offline fallback tetap menuju `index.html`.
- Ketiga route hash harus tetap dapat digunakan offline.
- PWA harus diuji dari browser dan mode Home Screen.

# 21. Main Risks and Controls

## Risk 1 — Monitor Regression

Penyebab:

- Perubahan DOM.
- Konflik CSS.
- Konflik JavaScript global.
- Chart dibuat dalam container tersembunyi.
- Event listener berubah.

Control:

- Monitor tidak direfactor pada V2.0.
- Gunakan CSS scope.
- Buat baseline.
- Uji hasil numerik.
- Uji grafik setelah kembali dari halaman lain.

---

## Risk 2 — CSS Collision

Penyebab:

- Report HYNC memiliki selector umum seperti:
  - `body`
  - `.card`
  - `button`
  - `input`
  - `.panel`

Control:

- Scope CSS Report.

Contoh:

```css
#page-report .report-card {}
#page-report .report-button {}
#page-report .report-panel {}
```

Hindari selector global dari generator sumber.

---

## Risk 3 — JavaScript Global Collision

Penyebab:

- Variabel `state`.
- Fungsi `setStep`.
- Fungsi `goToStep2`.
- Elemen `fileInput`.

Control:

- Gunakan ES module.
- Gunakan namespace.
- Gunakan prefix ID.

Contoh:

```text
hync-prev-text
hync-file-input
hync-step-1
hync-output
```

---

## Risk 4 — State Lost During Navigation

Penyebab:

- Page DOM dihancurkan saat route berubah.
- Page dirender ulang dari awal.

Control:

- Hide/show page.
- Pertahankan page instance.
- Jangan reset state saat route berubah.

---

## Risk 5 — PWA Cache Stale

Penyebab:

- Cache version tidak dinaikkan.
- File baru tidak masuk APP_SHELL.
- Browser menahan service worker lama.

Control:

- Naikkan cache version.
- Dokumentasikan update.
- Uji clean install.
- Uji update dari versi lama.
- Sediakan petunjuk clear cache jika diperlukan.

---

## Risk 6 — Contractor Mapping Duplication

Penyebab:

- Monitor dan Report memiliki daftar DT masing-masing.
- Mapping dapat berbeda.

Control:

- Gunakan single source of truth.
- Gunakan adapter.
- Dokumentasikan konflik.
- Jangan mengubah mapping tanpa validasi operasional.
