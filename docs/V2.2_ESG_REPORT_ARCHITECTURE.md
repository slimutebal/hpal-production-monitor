## 1. Executive Summary

V2.2 adds **ESG** as a third Report buyer, alongside HYNC and SLNC, on the same shared `#/report` route and UI. Before this change, uploading an ESG workbook was silently misrouted into the HYNC/SLNC parser and failed with a misleading error (`Kolom "流水号" tidak ditemukan di sheet "WS 050826 S2"`) — confirming the workbook was structurally valid ESG data being forced through the wrong parser. V2.2 fixes this at the root: a new **deterministic workbook dispatcher** decides HYNC/SLNC vs. ESG Format A vs. ESG Format B vs. unsupported/ambiguous *before* any parser runs, and only ever sends a workbook to the HYNC/SLNC parser when it shows zero ESG structural evidence.

ESG is genuinely different from HYNC/SLNC in several confirmed ways (not assumed): two distinct real-world workbook layouts must both be supported by one buyer identity; net weight is stored in tons, not kilograms; the previous-shift report is optional (HYNC/SLNC's remains mandatory, unchanged); and the manpower/PIC section uses "ATQ" instead of "AWK" as the partner label. Where HYNC/SLNC's existing shared engine (`shared-report-profile.js`) genuinely already covers ESG's needs (loading areas, ore-class thresholds, contractor lookup, Daily/WTD/MTD/YTD math, report-text structure), it is reused unmodified or with a single, narrowly-scoped, default-safe parameter addition — not duplicated.

## 2. Scope

**Implemented:**
- ESG buyer identity (`'ESG'`, not Monitor's legacy `'EIEB'`).
- Deterministic detection and parsing of both real ESG workbook formats (Format A, Format B).
- A workbook dispatcher (`report-workbook-dispatcher.js`) that routes every upload to the correct parser, never by elimination.
- ESG-specific aggregation (shift detection, dome+grade grouping, contractor resolution) producing the same `parsed` shape HYNC/SLNC already use.
- Previous Report optional for ESG only, with zero-accumulation semantics when empty.
- `FPP ESG` previous-report token detection, three-way ambiguity handling.
- Buyer mismatch/invalid-workbook protection extended to ESG, with ESG-specific popup content.
- Dynamic PIC/Manpower field labels (`AWK` vs. `ATQ`) without renaming any existing form-element ID.
- ESG-specific file-success summary and error messages.
- Service worker cache bump + new modules added to `APP_SHELL`.

**Out of scope (unchanged, confirmed untouched):**
- Loading-area options (`BR1`/`BR23E`/`BR23W`/`DS` — unchanged, ESG uses the same set).
- Contractor assignments (`contractor-adapter.js` — zero diff).
- HYNC/SLNC calculations, output, or buyer detection (`hync-profile.js`, `slnc-profile.js` — zero diff; `shared-report-profile.js` — one additive, default-safe parameter only).
- Monitor (`index.html` — zero diff).
- Settings, authentication, licensing, backend, frameworks, dependencies.

## 3. Live Workbook-Dispatch Architecture

`js/pages/report/profiles/report-workbook-dispatcher.js` is the single place in the active application that decides where an uploaded workbook goes. `report-page.js`'s `handleFileChange()` calls only `parseUploadedWorkbook(workbook)` — it contains no dispatch logic itself.

```text
parseUploadedWorkbook(workbook)
  │
  ├─ detectEsgWorkbookFormat(workbook)
  │
  ├─ ESG_FORMAT_A or ESG_FORMAT_B  → parseEsgWorkbook(workbook)         [esg-profile.js]
  ├─ AMBIGUOUS                     → throw "Format workbook ESG ambigu…"
  ├─ UNSUPPORTED + any ESG marker  → throw "Format ESG tidak didukung…"
  └─ UNSUPPORTED + zero ESG marker → parseWeighbridgeWorkbook(workbook)  [shared-report-profile.js, UNCHANGED]
```

The "UNSUPPORTED + any ESG marker" branch is what actually fixes the original bug: a broken/incomplete ESG file (e.g. a template missing one required column) is **not** silently sent to the HYNC/SLNC parser — it gets an ESG-specific error instead. This required one small, well-justified addition to the Phase 1 detector: `scanMarkerCoverage()` (`adapters/esg-adapter-utils.js`), which reports the best partial marker-match found even when a full match fails, letting the dispatcher distinguish "this looks ESG-shaped but broken" from "this workbook has zero ESG evidence at all." Verified against a synthetic genuine-HYNC-header sample that this produces zero false positives (no textual overlap between HYNC's `流水号`/`车号`/etc. and either ESG format's markers).

Both parsers (`parseWeighbridgeWorkbook` and `parseEsgWorkbook`) converge on the same return shape (`sheetName, fileDate, records, domes, shiftLabel, shiftFallback, onShiftTon, onShiftRit, contractorCounts, totalADT, totalDT, unmatchedTrucks, dateMismatch, workbookBuyer, workbookBuyerIssues`, plus `workbookFormat` — `null` for HYNC/SLNC, `'ESG_FORMAT_A'`/`'ESG_FORMAT_B'` for ESG). This is what lets `report-page.js`'s existing `renderScaleDisplay`, `renderWarnings`, `renderDomeList`, and `calculateTotals` work on an ESG-parsed workbook with no new per-buyer branching in those functions.

## 4. ESG Format A Integration

Format A ("ATQ" style — confirmed real sample: `DATA TIMBANGAN 5 AGUSTUS 2026 SHIFT 2.xlsx`) is detected by a 2-row header window (`Vehicle No`, `Date`, `Time Loaded`, `Cargo Weighing`, `Kode Dome`) plus at least one row whose Vehicle No starts with `SCM`. Positive ESG buyer evidence is a `"Stockpile ESG"` string found in the letterhead block above the header — the adapter does not rely on the shipment-code prefix (`Kode Sample`) alone, since that code varies per shipment and is not a stable buyer marker. `esg-format-a-adapter.js` is unchanged from Phase 1 except for the header-resolution/fallback logic it already had; no defect was found in it during Phase 2 integration testing.

## 5. ESG Format B Integration

Format B ("SCM raw data" style — confirmed real sample: `08月05日SCM-ESG送矿汇总表 (Data Timbangan Ore 05 Agustus 2026) NIGHT SHIFT.xlsx`) is detected by a single-row header (`NO.NOTA`, `NO. DT`, `PENERIMA`, `TIMBANGAN BERSIH`, `JAM TIMBANG ISI`, `TANGGAL`, `KODE ORE`) plus at least one row whose `NO.NOTA` starts with `20`. The workbook's separate pre-aggregated summary sheet is never selected as the source — not by name exclusion, but because it genuinely does not carry this format's required header markers at all. Positive ESG buyer evidence is the `PENERIMA` column equaling `"ESG-FPP"` (trimmed, case-insensitive) on every valid row.

**One real defect was found and fixed during Phase 2 integration testing** (via a from-scratch Python/openpyxl cross-check against the real Format B file, not by reading the code): the original `date-time-mismatch` rule required `TANGGAL` and the date embedded in `JAM TIMBANG ISI`'s text to match exactly, which incorrectly flagged ~40% of the real NIGHT SHIFT file's rows as invalid — `TANGGAL` correctly stays the shift's operational date while `JAM TIMBANG ISI` legitimately rolls into the next calendar day for loads weighed after midnight. Fixed in `esg-format-b-adapter.js` to accept a same-day-or-next-day relationship (day difference of 0 or 1); confirmed this restores the correct 475-row, 23,061.48-ton result.

## 6. Previous Report — ESG Handling

Confirmed via `report-page.js`'s `goToStep2()`: Previous Report is required for every buyer *except* one whose profile says otherwise. `profile-registry.js`'s `PROFILE_CONFIG` currently marks only ESG as `previousReportOptional: true`; HYNC and SLNC remain `false`, unchanged.

- **Empty Previous Report + ESG workbook (either format):** allowed. `goToStep2()` constructs a zero-accumulation `prev` object (`{ date: null, daily: {ton:0,rit:0}, wtd: {...}, mtd: {...}, ytd: {...} }`) instead of calling `parsePrevText()`. This is handed to `calculateTotals()` **completely unchanged** — that function's own `sameDate(prev.date, ...)` check already treats a `null` date as "no continuation," so every accumulator naturally resets to On Shift alone. No new calculation logic was written; the empty-ESG-previous-report rule is implemented entirely by constructing the right input to an existing, unmodified function. Verified: `Daily = WTD = MTD = YTD = On Shift` exactly, against the real Format A workbook's totals.
- **Non-empty ESG Previous Report:** parsed by the same, unmodified `parsePrevText()` HYNC/SLNC use (Date/Daily/WTD/MTD/YTD line format assumed identical, per the task's own instruction — not independently re-confirmed against a real ESG previous-report text sample, since none was available; see Section 11, Known Limitations). Must contain the `FPP ESG` token (see Section 7) or buyer resolution does not confirm.
- **Empty Previous Report + HYNC or SLNC:** still blocked — `previousReportOptional` is `false` for both, unchanged from V2.1.

## 7. Buyer Mismatch / Detection

`profile-registry.js`'s `buyerFromPrevText()` now checks three tokens (`FPP\s+HYNC`, `FPP\s+SLNC`, `FPP\s+ESG`, all case-insensitive, whitespace-tolerant). Two or more tokens present at once is `ambiguous` — the check was generalized from a 2-way boolean to a match-count comparison; for text containing only the original two tokens this is mathematically identical to the pre-existing check (confirmed by direct diff review). Never silently defaults to any buyer.

Full validation matrix (verified via a faithful Python port of `recomputeBuyerResolution()`, 14 scenarios, all passing):

| Previous Report | Workbook | Result |
| --- | --- | --- |
| HYNC | HYNC | Confirmed |
| SLNC | SLNC | Confirmed |
| ESG | ESG Format A | Confirmed |
| ESG | ESG Format B | Confirmed |
| *(empty)* | ESG Format A | Confirmed (zero previous accumulation) |
| *(empty)* | ESG Format B | Confirmed (zero previous accumulation) |
| *(empty)* | HYNC | Blocked |
| *(empty)* | SLNC | Blocked |
| HYNC | ESG | Blocked (mismatch) |
| SLNC | ESG | Blocked (mismatch) |
| ESG | HYNC | Blocked (mismatch) |
| ESG | SLNC | Blocked (mismatch) |
| Ambiguous (2+ tokens) | any | Blocked |
| any | Ambiguous ESG format | Blocked |
| any | Unsupported ESG-shaped workbook | Blocked |

Exact FPP numbers are never compared for any buyer, ESG included — only buyer identity.

**Popup content:** `report-page.js`'s `buildBuyerModalContent()` now branches on `reportState.workbookFormat` (non-null only for ESG) before falling into the existing HYNC/SLNC `备注`-prefix wording, routing to a new `buildEsgInvalidWorkbookContent()` that renders the ESG adapters' own row-level issue messages (already human-readable, Indonesian, with 1-based source-row numbers from Phase 1) grouped into workbook-level vs. row-level issues, titled `"Data ESG tidak valid"`, including the detected format and sheet name. The `AMBIGUOUS_PREVIOUS_REPORT` popup text was updated to mention all three buyer tokens.

## 8. Dynamic ESG Labels

`profile-registry.js`'s `getProfile(buyer)` now returns `partnerLabel` (`'AWK'` for HYNC/SLNC, `'ATQ'` for ESG) and `previousReportOptional`. `report-page.js`'s `updateBuyerUI()` uses these to:
- Set the `PIC {partnerLabel}` / `Manpower {partnerLabel}` `<label>` text via `label[for="hync-pic-awk"]` / `label[for="hync-mp-awk"]` selectors — **no existing form-element ID was renamed**; only the label text targeting is new.
- Toggle the `hync-req` (required-marker) class on the Previous Report `<label>` and update its hint text, based on `previousReportOptional`.
- All other dynamic strings (eyebrow, subtitle, workbook title/hint, footnote) were already buyer-agnostic string templates (`` `FPP ${buyer}` `` etc.) from V2.1 and needed no change to work for `'ESG'`.

`goToStep2()`'s required-field error messages (`"PIC AWK belum diisi."` etc.) are now profile-aware, reading the same `partnerLabel` so an ESG upload with a blank PIC field says `"PIC ATQ belum diisi."`, not the HYNC/SLNC wording.

## 9. Contractor Handling

`contractor-adapter.js` is untouched (confirmed zero diff). ESG vehicle IDs (`"SCM-LIM 930 DT"`) are resolved via `resolveEsgContractor()` in `esg-profile.js`, which tries the raw ID first, then a normalized form — mirroring `shared-report-profile.js`'s private `normalizeSlncDt`/`resolveContractor` exactly (same fallback order), duplicated rather than imported to keep the ESG layer's module boundary intact (same precedent as `classifyEsgOreClass`'s duplication in Phase 1).

**One ESG-specific addition, confirmed necessary and scoped only to `esg-profile.js`:** a small number of real ESG rows have a trailing period after "DT" (`"SCM-LIM 910 DT."`) that SLNC's regex (no evidence of this pattern in real SLNC data) does not strip. `normalizeEsgVehicleNo()`'s regex was changed from `/\s+DT$/i` to `/\s+DT\.?$/i` — found by running the real Format A file through the aggregation logic and checking each unmatched truck ID against the real `contractor-adapter.js` table before concluding it was a genuine gap. This recovered 2 of 21 originally-unmatched trucks in the real sample (confirmed both `"SCM-LIM 218"` and `"SCM-LIM 910"` are real, existing, unaffected entries in the approved table). `shared-report-profile.js`'s own `normalizeSlncDt` was **not** touched — zero HYNC/SLNC regression risk from this change.

Truck count is unique normalized-vehicle count, not ritase count (`Map` keyed by `vehicleNo`, same pattern as HYNC/SLNC). Unmatched contractors are non-blocking warnings (`unmatchedTrucks`, surfaced via the existing `renderWarnings()`), never a parser block — confirmed: the real Format A file has 19 genuinely-unmatched trucks (not in `contractor-adapter.js` at all, regardless of normalization) out of 81, and parsing still succeeds cleanly with those 19 listed as a warning.

## 10. Loading Areas & Report Output

ESG uses the same `AREA_OPTIONS` (`BR1`/`BR23E`/`BR23W`/`DS`) and `LOADING_POINT_ORDER` from `shared-report-profile.js`, unchanged — no ESG-specific loading-area code exists. The old `BR`/`BR23`/`DS` model from the local ESG HTML references was not restored.

`buildReportText()` (`shared-report-profile.js`) gained one additive parameter, `partnerLabel = 'AWK'`, used only on the two PIC/Manpower lines (`"PIC {partnerLabel} : …"`, `"Manpower {partnerLabel}  : …"`). Every pre-existing call site (HYNC, SLNC) that doesn't pass it produces **byte-identical** output to before — confirmed by direct diff review (the only change to the file) and by a text-fragment cross-check confirming `"PIC AWK"`/`"Manpower AWK"`/`"FPP HYNC"` are all still produced correctly with the default. For ESG (`partnerLabel: 'ATQ'`), confirmed output contains `"FPP ESG"`, `"PIC ATQ"`, `"Manpower ATQ"`, `"A. Ore Delivered to FPP ESG"`, and `"Pit DS"`/`"Pit BR1"`/`"Pit BR23E"`/`"Pit BR23W"` headings (current areas only — old `"Pit BR :"`/`"Pit BR23 :"` headings confirmed absent). "AWK" and "ATQ" are both 3 characters, so the existing hand-tuned column spacing on those lines is unaffected either way.

The reference HTML's `"Man Power and Suppor"` typo was never reproduced — `shared-report-profile.js` already says `"Man Power and Support"` correctly (confirmed unchanged, no fix was needed).

No ESG-specific report-text formatter was written — the shared builder covers ESG's confirmed requirements with the one parameter above. If a genuine ESG output-format difference is ever confirmed beyond partner label (see Section 11), it should be added the same way: a parameter with a default matching current HYNC/SLNC behavior, not a duplicated builder.

## 11. Known Limitations / Unresolved Evidence

- **No real ESG previous-report text sample was available.** The `FPP\s+ESG` token pattern and the assumption that ESG's Date/Daily/WTD/MTD/YTD accumulation-line format matches HYNC/SLNC's exactly are both extrapolations from the task's own instructions and the local HTML references' source code, not independently confirmed against a real pasted WA-format ESG report.
- **Real in-browser testing was not performed for this task.** See Section 12 for what was and wasn't verified, and Section 13 for the required manual test checklist.
- **19 of 81 unique trucks in the real Format A/B sample are not in `contractor-adapter.js`** regardless of normalization — a genuine, pre-existing data gap in the approved contractor table, not something this task is in scope to fix (contractor assignments were explicitly out of scope). Surfaced correctly as a non-blocking warning.
- **ESG's "PIC ATQ"/"Manpower ATQ" fields are still internally keyed `picAwk`/`mpAwk`** in `reportState.inputs` (per the task's explicit allowance not to rename existing keys to avoid regression risk) — only the visible label text is buyer-driven.
- The two ESG workbook formats' relative currency/precedence (which one is the "current" approved template, if either is being phased out) is not addressed — both are supported permanently and equally per the task's requirement.
